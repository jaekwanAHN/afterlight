# AFTERLIGHT

브라우저에서 플레이하는 2D Survivors-like 게임. 어둠이 몰려오는 필드에서 경험치를 모으고 무기를 강화하며 **10분 동안 생존**합니다. 별도 계정, 서버 DB, 이미지 에셋 다운로드가 필요하지 않습니다.

## 실행

Node.js 22.12 이상(짝수 LTS 버전)과 npm이 필요합니다. 테스트 도구를 포함한 전체 환경은 **Node.js 24**를 권장하며 이 버전에서 검증했습니다.

```bash
cd /mnt/e/solo_project/survivor
npm install
npm run dev
```

브라우저에서 **http://localhost:3000**을 열고 **START SURVIVING**을 누르세요. `/game`에서도 같은 게임을 시작할 수 있습니다. 다른 앱이 3000번 포트를 사용하면 `npm run dev -- --port 3100`으로 실행할 수 있습니다.

프로덕션 실행:

```bash
npm run build
npm run start
```

개발 서버를 종료한 뒤 같은 포트에서 프로덕션 서버를 실행하세요. 외부 폰트나 원격 이미지에 의존하지 않습니다.

## 조작법

| 입력                     | 동작                                                          |
| ------------------------ | ------------------------------------------------------------- |
| WASD / 방향키            | 이동. 대각선 속도 정규화                                      |
| 터치 드래그              | 손가락이 닿은 곳을 중심으로 하는 플로팅 조이스틱 (모바일)     |
| ESC                      | 일시정지 / 계속하기                                           |
| A / D, ← / →             | 레벨업 화면에서 강화 카드 이동 (양 끝에서 순환)               |
| Enter / Space, 카드 클릭 | 선택한 강화를 적용하고 계속하기                               |
| PLAY AGAIN               | 새로고침 없이 새 게임 시작                                    |
| 설정                     | 피격·사망 효과, 배경 그리드, 효과음·배경음악 켜기/끄기와 볼륨 |

공격은 자동입니다. 적을 처치하면 나오는 연두색 보석 가까이 이동해 경험치를 모으세요. 레벨업 화면에서는 마우스로 카드를 가리키면 키보드 선택 위치도 함께 따라갑니다. 탭을 떠나거나 창의 포커스가 사라지면 자동 일시정지합니다. 돌아온 뒤 직접 재개해야 합니다.

## 구현 기능

- 월드 좌표 기반 무한 필드, 플레이어 추적 카메라, 바닥 패턴과 랜드마크
- 기본 체력 100, 이동속도 220, 획득 반경 60, 0.5초 피격 무적
- Normal / Fast / Tank 3종: 서로 다른 색·형태·체력·속도·피해·경험치
- 뷰포트 바깥에서 지속 생성, 시간에 따른 생성 간격·개수·HP 증가
- 매 분 등장하는 보스: 순번에 따라 체력·속도·피해가 커지고, 다섯 가지 색·표정(분노·미소·가면·외눈·비웃음)이 순환하며 HUD 체력바도 같은 색으로 표시
- 무기 7종: 자동 발사 Magic Bolt(기본), 레벨업으로 획득하는 Orbit Guardian·부메랑·낙뢰·광선·충격파·화염 지대. 무기별 강화 단계 파일로 분리
- 패시브 강화: 이동속도, 최대 체력, 경험치 획득 범위, 체력 회복 (무한 강화 후보 포함)
- 필드 아이템: 자석(모든 보석 흡수), 폭탄(화면 안 적 제거), 회복(최대 체력 40%). 약 30초마다 생성되고 줍기 전까지 남아 있음
- 적 사망, 처치 수, 경험치 드롭·흡수, 초과 경험치를 보존하는 연속 레벨업
- 중복 없는 강화 카드 3개, 최대 단계 후보 제외, 후반 무한 강화 후보
- 시작 / 일시정지 / 레벨업 / 게임 오버 / 10분 승리 / 재시작
- React HUD, 무기 표시, 보스 체력바, 키보드 포커스를 유지하는 모달, 키보드로 고르는 강화 카드
- 적 피격 flash, 플레이어 blinking, 사망 ring/particle 효과
- Web Audio로 합성한 효과음과 반복 재생되는 절차적 배경음악. 오디오 파일 없음
- `localStorage` 최고 생존 시간·처치 수·레벨과 설정 저장, 손상되거나 차단된 저장소에 대한 복구
- 모바일 화면에서도 배치가 유지되는 UI, 플로팅 터치 조이스틱, ResizeObserver, DPR 대응

## 기술 스택

- Next.js **16.3.4**, App Router
- React / React DOM **19.3.0**
- TypeScript **5.9.3**, strict mode
- HTML5 Canvas 2D, requestAnimationFrame
- CSS, Vitest, Playwright, ESLint, Prettier

게임 엔진 라이브러리는 사용하지 않습니다. 원·다각형 기반 Canvas 렌더링으로 MVP의 기능을 구현할 수 있어 외부 엔진과 비트맵 에셋 의존성을 추가하지 않았습니다. HUD 상태만 React에서 관리하므로 별도 전역 상태 라이브러리도 필요하지 않습니다.

`next.config.ts`의 `experimental.useTypeScriptCli: false`는 이 개발 환경에서 Next.js의 새 CLI 경로가 TypeScript `--showConfig` 출력을 파싱하지 못하는 문제에 대한 설정입니다. TypeScript 5 컴파일러 API로 **빌드 타입 검사는 그대로 수행**합니다. `ignoreBuildErrors`는 사용하지 않습니다.

```text
src/

  game/
    core/

      GameState.ts         # 엔진 상태와 읽기 전용 UI용 스냅샷 형상
      Simulation.ts        # 시스템 실행 순서
      records.ts           # 최고 기록 읽기·검증·저장
    audio/                 # Web Audio 효과음 합성, 절차적 배경음악
    config/                # 게임, 적·보스 외형, 아이템, 무기 밸런스
    entities/              # Player, Enemy, Projectile, Boomerang, BeamShot, Nova, FlamePatch, Item, ExperienceOrb, Effect
    systems/               # 입력(키보드·터치), 이동, 생성, 아이템, 전투, 충돌, 경험치, 레벨
    weapons/               # MagicBolt, Orbit, Boomerang, Storm, Beam, Nova, Flame, 타게팅
    upgrades/              # 무기별·패시브 강화 정의 및 선택/적용
    rendering/             # 렌더러, 배경, 엔티티 모양, 그리기 도구

```

## Game Loop와 상태 분리

```text
requestAnimationFrame
  → 실제 frame delta를 최대 0.05초로 제한
  → 누적 시간으로 1/60초 고정 simulation step 실행
      플레이어 이동·무적 감소
      → 적 생성 → 매 분 보스 생성 → 아이템 생성
      → 공간 그리드 구축·적 추적·separation
      → 이동 후 그리드 갱신
      → Magic Bolt 자동 공격·투사체 충돌
      → Orbit → 부메랑 → 낙뢰 → 광선 → 충격파 → 화염 지대
      → 플레이어 접촉 피해 → 아이템 획득
      → 사망·경험치 드롭·효과 정리
      → 경험치 흡수·레벨업
      → 먼 경험치 정리
  → Canvas 렌더링
  → 다음 RAF 예약
```

위치·속도·엔티티 배열·쿨다운·충돌은 `Game.state`에만 존재합니다. React에 엔티티 배열을 저장하거나 프레임마다 `setState`하지 않습니다. `Snapshot`은 체력·경험치·시간·처치 수·무기 단계·보스 체력·강화 선택지만 담으며 **0.1초 간격 또는 상태 변경 이벤트**에서 React로 전달합니다.

`idle | playing | paused | levelup | gameover | victory` 상태 중 `playing`에서만 시뮬레이션이 진행됩니다. 렌더 루프는 유지되어 resize에 대응하지만, 게임 오버·승리 이후 엔티티·게임 시간은 갱신하지 않습니다. 재시작은 뷰포트만 유지하고 모든 게임 상태와 타이머, 그리드를 초기화합니다. unmount 시 RAF·입력·resize·visibility 리스너를 정리합니다.

## 밸런스

`src/game/config`와 `src/game/upgrades/upgrades.ts`에서 조정합니다.

| 시점       | 변화                                                            |
| ---------- | --------------------------------------------------------------- |
| 시작       | Normal, 생성 간격 0.8초                                         |
| 60초       | Fast 추가                                                       |
| 매 60초    | 보스 등장. n번째 보스는 체력 ×(1 + 0.55(n−1)), 속도·피해도 증가 |
| 180초      | Tank 추가                                                       |
| 매 120초   | 생성 묶음 크기 증가                                             |
| 지속       | `1 + elapsed / 120`으로 생성 간격 감소                          |
| 300초 이후 | 적 체력 증가                                                    |
| 600초      | Victory                                                         |

경험치 요구량은 `floor(10 × 1.25^(level - 1))`입니다. 기본 마법탄은 피해 10, 쿨다운 0.6초, 속도 500, 발사 수 1입니다. 마법탄 외의 무기는 기본 장착이 아닌 레벨업 선택지로 획득합니다. 보스 외형은 `enemyConfig.ts`의 `BOSS_LOOKS`에서, 아이템 주기는 `itemConfig.ts`에서 조정합니다.

## 성능 설계와 확인

- 64px 공간 그리드로 적 separation·플레이어 접촉·투사체·회전 무기 충돌 후보를 제한합니다.
- separation은 주변 적 최대 16개까지만 반영합니다. 전체 적 쌍 O(N²) 비교는 하지 않습니다.
- 가장 가까운 적 탐색은 공격 쿨다운 종료 시에만 O(N)으로 실행합니다.
- 충돌은 제곱 거리로 검사하고, 빠른 투사체는 swept-circle 방식으로 관통 누락을 막습니다.
- 화면 밖 엔티티는 그리지 않습니다. 멀어진 적은 화면 밖으로 재배치합니다.
- 적 900개, 투사체 400개 상한을 둡니다. 경험치가 1,200개 이상이면 먼 보석을 지역별로 합치되 경험치 총량을 보존합니다.
- DPR은 `min(devicePixelRatio, 2)`로 고해상도 선명도와 렌더 비용을 절충합니다.
- pooling은 아직 사용하지 않습니다. 추후 실제 GC 프로파일에 따라 도입할 수 있습니다.

```bash
npm run perf
```

520 enemies / 220 projectiles / 320 orbs를 넣어 시뮬레이션 시간을 측정합니다. 개발 환경에서 180스텝 측정 결과 중앙값 **1.46ms**, p95 **2.57ms**였습니다. 이 수치는 **Canvas 렌더링을 제외**하며 실제 PC Chrome 60 FPS를 보장하지 않습니다. 기기·해상도별 성능 프로파일링이 추가로 필요합니다.

## 검증 명령

```bash
npm run lint
npm run typecheck
npm run test
npm run build
```

충돌, 이동 정규화, 입력 cleanup, 생성 위치·난이도, 공격·사망·드롭, 경험치 보존, 강화 중복/상한/실제 적용, 회전 무기 재피격 간격, 상태 전환·시간 정지·재시작·승리, 저장소 오류, 프레임률 독립성과 부하를 검사합니다.

브라우저 테스트:

```bash
npx playwright install chromium
npm run test:e2e
```

Playwright가 3100번 포트의 개발 서버를 시작합니다. 시작→키보드→일시정지→설정→재시작, 실제 자동 전투→레벨업→게임 오버→기록 저장, 모바일 390px/DPR 2를 검사합니다. 자동 전투 테스트는 Playwright 가상 시간을 사용하며 게임 엔진을 외부에 노출하거나 게임 상태를 조작하지 않습니다. 600초 승리 경계는 엔진 통합 테스트에서 검증합니다. 스크린샷과 실패 시 trace는 `test-results/`에 생성됩니다.

프로덕션 빌드도 `npm run build` 후 `PLAYWRIGHT_USE_PRODUCTION=1 npm run test:e2e`로 같은 시나리오를 확인할 수 있습니다.

이미 설치된 Chromium이 있다면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 환경변수로 실행 파일을 지정할 수 있습니다.

## 알려진 제한사항

- 엘리트 적, 진화 무기, 캐릭터 선택은 포함하지 않았습니다.
- 최고 기록과 설정만 해당 브라우저에 저장합니다. 게임 도중 저장·계정 동기화는 없습니다.
- 보스 외형은 5종이 순환하므로 6번째 보스부터는 1번째와 같은 모습입니다.
- 장시간 실제 플레이에 따른 후반 밸런스 튜닝과 여러 GPU/4K 환경의 FPS 측정은 추가 작업입니다.
- 시각 효과 설정은 전투 flash/blink/사망 효과에 적용됩니다. 게임을 읽는 데 필요한 투사체·보석·회전 무기는 계속 표시됩니다.
